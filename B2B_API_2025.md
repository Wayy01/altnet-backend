# B2B API – 2025 (Translated and Formatted in Markdown)

## Service Overview

The service is designed to obtain data on products, stock balances, and prices.
**Server address:** `https://portal.it-ultra.com/b2b/ru/ws/b2b.1cws?wsdl`

The service provides **7 main functions**:

1. `requestData` – general request function to get data
2. `isReady` – checks if requested data is prepared and ready for transfer
3. `getDataByID` – retrieves previously requested data
4. `putData` – general data transfer function (not used)
5. `putOrder` – sends order data
6. `CommitReceivingData` – confirms data reception
7. `testService` – checks connection to the service

---

## 1. requestData

```xml
<soap:Envelope xmlns:soap="http://www.w3.org/2003/05/soap-envelope" xmlns:ult="http://ultra.b2b.md">
  <soap:Header/>
  <soap:Body>
    <ult:requestData>
      <ult:Service>?</ult:Service>
      <ult:all>?</ult:all>
      <ult:additionalParameters>?</ult:additionalParameters>
      <ult:compress>?</ult:compress>
    </ult:requestData>
  </soap:Body>
</soap:Envelope>
```

### Attributes

- **Service** – predefined name of the table to load (string)
- **All** – if true, load all data; if false, only new and changed data since the last confirmed load (see CommitReceivingData) (boolean)
- **additionalParameters** – string of additional parameters, used with some services
- **compress** – if true, data is compressed during transfer; compression currently available only for 1C-based systems

### Predefined Service Values

| Service | Description | Additional Parameters |
|---------|-------------|----------------------|
| **NOMENCLATURE** | List of products with attributes, extra fields (propertyList), characteristics (characteristicList), and attached images (imageList) | Not used |
| **PROPERTIES** | List of product properties; use with UUID of the product group for filtering large datasets | UUID of product group |
| **NOMENCLATURETYPELIST** | List of product groups with extra fields (propertyList) and characteristic properties (propertyCharacteristicList) | Not used |
| **BRAND** | List of brands with attributes and image | Not used |
| **PARENTLIST** | Common parent list for hierarchical structures; used only with NOMENCLATURE and NOMENCLATURETYPELIST | All = true; additionalParameters = NOMENCLATURE or NOMENCLATURETYPELIST |
| **PRICELIST** | List of prices by product and characteristic UUID | Two variants: (1) All=true for all prices, (2) All=false and additionalParameters=product UUID |
| **BALANCE** | List of stock balances by product and characteristic UUID | Two variants: (1) All=true for all balances, (2) All=false and additionalParameters=product UUID |
| **RATES** | Current currency rate structure | — |

The function returns an operation GUID, which can later be used to fetch data.

## 2. isReady

```xml
<soap:Envelope xmlns:soap="http://www.w3.org/2003/05/soap-envelope" xmlns:ult="http://ultra.b2b.md">
  <soap:Header/>
  <soap:Body>
    <ult:isReady>
      <ult:ID>?</ult:ID>
    </ult:isReady>
  </soap:Body>
</soap:Envelope>
```

### Attribute

- **ID** – operation GUID

Returns a boolean indicating whether data is ready for transfer.

## 3. getDataByID

```xml
<soap:Envelope xmlns:soap="http://www.w3.org/2003/05/soap-envelope" xmlns:ult="http://ultra.b2b.md">
  <soap:Header/>
  <soap:Body>
    <ult:getDataByID>
      <ult:ID>13bd18a7-96e3-47b3-ac2c-e65f97028f6c</ult:ID>
    </ult:getDataByID>
  </soap:Body>
</soap:Envelope>
```

### Returns

An object response with:

- **message** – contains "OK" if data formed correctly, or an error message
- **data** – XML data according to the schema

### Recommended Data Retrieval Order

1. Parent product groups
2. Product groups
3. Brands
4. Product parents (if hierarchy needed)
5. Products
6. Exchange rates
7. Prices
8. Stock balances
9. Translations
10. Properties

This ensures all referenced GUIDs are available and reduces payload size.

## 4. CommitReceivingData

```xml
<soap:Envelope xmlns:soap="http://www.w3.org/2003/05/soap-envelope" xmlns:ult="http://ultra.b2b.md">
  <soap:Header/>
  <soap:Body>
    <ult:CommitReceivingData>
      <ult:Service>?</ult:Service>
    </ult:CommitReceivingData>
  </soap:Body>
</soap:Envelope>
```

### Attribute

- **Service** – predefined name of the loaded table (string)

**Possible values:** NOMENCLATURE, NOMENCLATURETYPELIST, BRAND

Used to confirm data receipt and clear records of modified elements.

## 5. Data Structures

### Product Group Parents (`<parent>`)

Fields include:

- name, code, UUID, object, active, orderBy
- **image** – description and file paths
- Recursive `<parent>` elements for hierarchy

### Product Groups (`<nomenclatureType>`)

Includes attributes like:

- name, code, UUID, parent, active, orderBy, quantity
- image, propertyList, and propertyCharacteristicList

Each property includes:

- **property** (name, code, UUID)
- **value** (type, simpleValue)
- Flags: filter, modification
- **propertyGroup** for grouping

### Brands (`<brand>`)

Contains:

- name, code, UUID
- **image** with paths (internal and global)

### Nomenclature (Products)

Complex structure with product details, including:

- General fields (UUID, name, code, article, etc.)
- Hierarchical links (parent, nomenclatureType, brand)
- Lists of characteristics, properties, and images
- Barcode list
- Attributes for services, warranties, and active status

### Exchange Rates (`<rate>`)

- **rate** – current currency rate
- **valute** – structure describing the currency (name, code, UUID)

### Prices (`<price>`)

- **UUID** – product ID
- **Characteristic** – characteristic UUID
- **Price** – value in specified currency
- **PriceType** – includes currency UUID and price type data

### Balances (`<balance>`)

- **UUID** – product UUID
- name, code
- **Characteristic** – characteristic UUID
- **quantity** – warehouse quantity
- **quantityShowroom** – showroom quantity

### Translations (`<translationList>`)

Contains 3 logical sections:

1. **nomenclatureRequisitesList** – translations for attribute names
2. **nomenclatureRequisitesValueList** – translations for attribute values
3. **objectPropertyValueList** – translations for linked values

Each contains value in both 1C format (`ru='' en='' md=''`) and JSON format:

```json
{ "ru": "", "en": "", "md": "" }
```

### Properties (`<nomenclatureProperty>`)

Defines product properties with a propertyList including:

- **property** (name, code, UUID)
- **value** (type, simpleValue)
- Optional filter, modification, propertyGroup

## 6. putOrder

Defines the structure of order transmission.

```xml
<xs:complexType name="order">
  <xs:sequence>
    <xs:element name="UUIDLine" type="xs:string"/>
    <xs:element name="client" type="xs:string" nillable="true"/>
    <xs:element name="date" type="xs:dateTime"/>
    <xs:element name="nomenclature" type="xs:string"/>
    ...
    <xs:element name="errorMessage" type="xs:string" nillable="true" minOccurs="0"/>
  </xs:sequence>
</xs:complexType>
```

### Main Fields

| Field | Type | Description |
|-------|------|-------------|
| **UUIDLine** | string | Unique line ID (required) |
| **client** | string | Client ID (required) |
| **date** | dateTime | Order date (required) |
| **nomenclature** | string | Product UUID (required) |
| **characteristic** | string | Characteristic UUID |
| **quantity, price, sum** | float | Required |
| **UUIDOrder** | string | Unique order UUID in Ultra |
| **reserve, confirmed, shipped** | boolean | Status flags |
| **canceled, delivery** | boolean | Cancellation and delivery flags |
| **plannedDate, reserveDate** | dateTime | Delivery and reserve dates |
| **orderNumber, orderNumberUltra** | string | B2B and Ultra order numbers |
| **sellingPrice, sellingSum** | float | Actual sale data |
| **error, errorMessage** | — | Used for error reporting |

### Order Status Retrieval

Use `requestData` with:

- **Service** = ORDERSSTAT
- **additionalParameters** = list of order UUIDs separated by commas
- **compress** = false

Returns orderList structure with current order state.

⚠️ **Note:** When sending an order for the first time, prices and totals may update to current values. The order is fully uploaded once the UUIDOrder field is filled.
